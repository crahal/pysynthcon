# Replication and validation

The four notebooks in `empirical_examples/` use only settings from major
methodological papers. Each downloads immutable public bytes with requests,
verifies SHA256, checks a reference specification, and runs all twelve
interfaces on a shared outcome panel. Executed outputs are committed.

Each notebook also exports three publication figures (reference paths,
ATT/pretreatment-fit summary, and shared-scale effect panels) as PDF, SVG and
300 dpi PNG, with a CSV of comparison values. The [plotting guide](plotting.md)
documents units, timing, scale and export conventions. Figures show point
estimates without confidence intervals; the post-period shading denotes time.

## What each check establishes

| Example | Reference specification | Numeric target | Predeclared tolerance |
|---|---|---|---|
| California | R synthdid no-covariate example, 1989 onset | ATT −15.603827872733849 | absolute $10^{-6}$ |
| Basque | pysyncon/Synth predictor specification | 1975–1997 ATT −0.6995647842110987; Catalonia/Madrid weights 0.850816306/0.149183694 | 2.5% relative ATT; 0.025 absolute weights |
| Germany | pysyncon ADH two-stage V specification | 1990–2003 ATT −1555.1346777620479 | 2.5% relative |
| Kansas | authors' R augsynth no-covariate vignette | Ridge ASCM ATT −0.0401 | absolute 0.001 |

California's target was independently generated by running the pinned R
synthdid source and also matches the paper's rounded −15.6 result. The Basque
and Germany high-precision numbers are **upstream implementation references**,
not numbers printed to that precision in the papers. Their tolerance is the
upstream parity suite's stated tolerance. Kansas uses the authors' vignette's
printed value. Differences in third-decimal donor weights can arise from
nested optimization and numerical environments; tolerances are not widened
after seeing a run.

California's SDID standard error is also replicated with the authors' exact
200-draw plan. `california_paper_inference(panel, estimate)` uses an isolated
base-R process to generate Mersenne-Twister/Inversion/Rejection permutations
with `set.seed(12345)`, then performs all SDID refits in Python. The alphabetical
donor order and historical time window are checked. The standard error is
**8.36799308138054**, matching Table 1's rounded **8.4**, with an independent-R
absolute tolerance of `1e-9`. The seed is specified in the authors'
[paper-results vignette](https://github.com/synth-inference/synthdid/blob/70c1ce3eac58e28c30b67435ca377bb48baa9b8a/vignettes/paper-results.Rmd).
A NumPy seed produces a different draw plan, so it is unsuitable for claiming
replication of this particular finite-draw standard error. See the
[inference guide](inference.md) for the API and draw-level checks.

The Basque fitting period is 1960–1969; the common-comparison ATT begins 1970,
while the upstream reference ATT uses 1975–1997. Its upstream donor pool also
includes Spain's aggregate, with zero fitted weight. Germany's historical
training and predictor convention includes 1990, even though the comparison
Panel defines 1990 as post-treatment. This is isolated in `replicate`, explained
in the notebook, and never used by the generic native estimators. Kansas uses
2012.25 as in the authors' example; the outcome is a natural logarithm.

The California dataset contains outcomes only. The notebook reproduces the
SDID specification, **not** ADH (2010)'s original covariate-based SCM predictor
specification. Native outcome SCM on that dataset is a separate comparison.

## Independent numerical checks

Offline fixtures in `tests/fixtures` contain small artificial numeric panels
and outputs generated by R, not by the Python estimators. SDID is checked
against R's donor weights, time weights and ATT. The current SCUL default is
checked against independently generated original-R fits with glmnet 4.0-2,
including all three selection rules. ISC is checked against MSCMT 1.4.0,
including covariate groups and the donor-sampling stream across individuals.
These checks live in `tests/test_r_references.py`; their generator is
`tests/fixtures/reference_backends.R`.

Separate legacy tests check the explicitly selected native-Python SCUL
approximation against glmnet's solver on a common lambda grid. Lasso prediction
tolerances allow its stopping error; its alpha grid and optimal penalty are
checked separately. The analytic orthogonal-design lasso test also verifies
penalty normalization and reconstruction on original units.

Other tests cover known effects, multi-treated additive models, label/order
alignment, no treated-post leakage, invariance, nearest-donor selection,
case aggregation, placebo exclusion/rank rules, HTTP errors, hashes and
corrupt caches. Adapter tests compare returned predictions to the actual
upstream fitted object's predictions.

## Re-run

```bash
python -m pip install -r requirements-replication.txt
python -m pip install -e '.[docs,dev]'
# First install R, C/Fortran development tools and GLPK headers (see guide below).
python scripts/install_r_references.py --library .r-library
python -m pytest
python -m pytest -m network
python scripts/execute_notebooks.py --output-dir /tmp/pysynth-notebooks
```

The tested numeric environment uses Python 3.12, NumPy 2.0.2, SciPy 1.13.1,
pandas 2.3.3 and scikit-learn 1.7.2; all principal replication requirements
are pinned. BLAS and platform differences can still matter. Run with
`OPENBLAS_NUM_THREADS=1` for stable, economical small-panel computation.

R is required for the default SCUL and ISC fits and for their integration
tests. The native Python tests remain independent of R and network access.
See the [R installation guide](reference_backends.md).

To independently re-run the legacy native-Python SCUL and SDID point-estimate
references without rewriting fixtures, install the R packages `glmnet` and
`jsonlite`, then run:

```bash
python scripts/validate_r.py
# For a custom R library location:
python scripts/validate_r.py --r-library /path/to/R-library
```

This legacy SCUL fixture tests `backend="python", selection="min"`; it does
not validate the current original-R default. It used R 4.6.2 and glmnet 5.2.
Its selected penalty
matches to $10^{-9}$. Default glmnet coefficient stopping leaves a maximum
path difference of about 0.007 outcome units on this smooth test panel;
the test permits 0.01 and also checks a high-precision glmnet refit at
$10^{-5}$ absolute path tolerance. These are solver parity checks, not a
precision claim about a causal effect in the original SCUL study.

## Boundaries of the empirical claims

Applying SCUL, ISC or 2SISC to a classic aggregate dataset is a new
application. It does not reproduce the original SCUL scanner-data study,
the Vagni–Breen motherhood study, or costofcare's survey analysis. The original
data access and case construction are not supplied by this repository.
`IndividualSC` uses each case's full eligible pool; `TwoStageIndividualSC`
adds nearest-neighbor screening before the same weight fit. Both appear
separately in every comparison notebook. MSCMT now performs the original nested predictor-weight fitting, with
50 donor resamples in the notebooks. The original survey-specific variables,
eligibility rules and microdata are still required to reproduce those
studies' empirical estimates; no invented targets are assigned to them.


## Full fitting and comparison with earlier software

The empirical notebooks now estimate pysyncon SCM predictor importance, retain
all pre-outcome lags, and run all ten SyntheticControlMethods starts. SCUL uses
the original fold-specific glmnet paths and median penalty; ISC and 2SISC use
MSCMT and 50 donor resamples. Original SDID placebo inference uses 200 refits.
Numerical solver recovery is documented in the backend guide; it changes no
statistical objective and records each optimizer attempt.

SCUL needs a feasible rolling-validation design. The explicit initial-window /
horizon choices are California 5/12, Germany 14/14, Kansas 16/16, and Basque
3/5. The Basque pre-period is too short to validate a 28-period horizon; this
limitation is visible rather than hidden by an automatic shortcut. These are
new applications of the original algorithm, not original-paper calibrations.

`empirical_examples/baselines/32d4f97` archives the preceding software CSVs
unchanged. The notebooks export current-minus-previous ATT tables separately
from academic source comparisons. Runtime and solver diagnostics accompany
the results. Floating-point libraries and R package versions are recorded;
algorithmic parity does not imply bitwise equality across arbitrary machines.
